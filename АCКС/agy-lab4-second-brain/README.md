# Персональний Local-First Second Brain (Студентський конспект)

Локальна персональна система управління знаннями (PKM — Personal Knowledge Management) для студента інженерних спеціальностей. Побудована за методологією **PARA**, розміткою **Markdown**, метаданими **YAML Frontmatter** та підтримкою двосторонніх зв'язків **`[[Wikilinks]]`**.

Працює **на 100% автономно, без серверів, без сторонніх залежностей та без платних зовнішніх API**.

## 2. Архітектура та організація простору (Методологія PARA)

Організація бази знань базується на принципах методології **PARA** (Projects, Areas, Resources, Archives), адаптованої до академічного процесу:

```
agy-lab4-second-brain/
├── notes/
│   ├── Inbox/       # 📥 Вхідні: швидка фіксація необроблених думок і конспектів
│   ├── Projects/    # 🎯 Проєкти: активні роботи з дедлайнами (лабораторні, курсові)
│   ├── Areas/       # 🧭 Сфери: довгострокові навчальні дисципліни та оглядові MOC
│   ├── Resources/   # 📖 Ресурси: довідники, статті, патерни проектування, конспекти книг
│   └── Archives/    # 📦 Архіви: завершені та захищені роботи минулих семестрів
├── templates/
│   └── note-template.md # Стандартний шаблон нової нотатки
├── src/             # Вебінтерфейс (index.html, styles.css, app.js, server.py)
├── docs/            # Архітектурна документація (ARCHITECTURE.md)
├── tests/           # Автоматизовані тести (verify.html)
└── .agents/skills/  # Спеціалізовані workspace-навички для AI-асистента
```

### Призначення категорій:
* **`notes/Inbox/`** — буфер вхідних нотаток. Сюди потрапляють усі нові записи під час лекцій або швидкі чернетки (`type: fleeting`, `status: draft`).
* **`notes/Projects/`** — активні навчальні та інженерні завдання з дедлайном і фінальним результатом (наприклад, курсовий проєкт або розгортання K8s-кластера).
* **`notes/Areas/`** — фундаментальні навчальні сфери та дисципліни, які не мають фіксованого терміну закінчення (наприклад, курс комп'ютерних систем), а також оглядові **MOC (Map of Content)**.
* **`notes/Resources/`** — корисні теоретичні матеріали багаторазового використання: довідники з системного API Linux, архітектурні шаблони, опис кеш-пам'яті, конспекти літератури.
* **`notes/Archives/`** — неактивні матеріали: успішно захищені звіти лабораторних робіт минулих модулів та закриті семестрові предмети (`status: archived`).

### Модель нотатки (YAML Frontmatter):
Кожен документ зберігається як окремий файл `.md` зі структурованим заголовком і трьома обов'язковими H2-секціями:
```markdown
---
title: "Назва нотатки"
created: "2026-11-16 11:30:00"
updated: "2026-11-16 11:30:00"
tags:
  - "архітектура"
  - "linux"
status: "active"
type: "resource"
source: "джерело інформації"
---

## Короткий зміст
Лаконічний опис (1-3 речення).

## Основні твердження
- Теза 1
- Теза 2

## Пов'язані нотатки
- [[Назва іншої нотатки]]
```

### Функціональні обов'язки навички:
1. **Автоматична класифікація:** аналіз чернеток із `notes/Inbox` та визначення оптимальної цільової папки PARA (`Projects`, `Areas`, `Resources`, `Archives`).
2. **Збагачення метаданих:** підбір релевантних нормалізованих тегів, оновлення статусу та типу документа.
3. **Резолюція зв'язків:** пошук смислових перетинів з існуючою базою знань і формування двосторонніх посилань `[[Назва нотатки]]`, включаючи оновлення MOC-карт.
4. **Формування журналу змін:** генерація структурованої порівняльної таблиці («Поточне значення» $\rightarrow$ «Пропозиція» $\rightarrow$ «Обґрунтування»).
5. **Суворий протокол безпеки:**
   - **Заборона самовільного переміщення:** асистент **ніколи** не переміщує і не видаляє файли без прямої команди користувача («Так/Ні»).
   - **Недопущення галюцинацій джерел:** суворо заборонено додумувати джерела — зберігається лише автентичне джерело автора.

## 4. Обмеження системи

1. **Пісочниця браузера (Browser Sandbox):** оскільки застосунок є клієнтським і не потребує фонового бекенду, прямий запис файлів на диск без відома користувача обмежений політикою безпеки браузера. Нові нотатки зберігаються у `localStorage`, а для внесення змін на диск використовується кнопка «💾 Зберегти як .md» або пакетний імпорт папки `notes/`.
2. **Синхронізація між пристроями:** система не залежить від закритих хмарних сховищ. Синхронізація конспектів між ПК та ноутбуком рекомендується через відкриті інструменти: локальний **Git-репозиторій** або P2P-синхронізатор **Syncthing**.
3. **Обробка вкладень:** система орієнтована на текстові конспекти та лінійну графіку Markdown; для великих PDF-підручників рекомендується збереження у локальну директорію `assets/` з посиланням у нотатці.
