# Інструкція навички: Обробка та класифікація нотаток Second Brain

Ця навичка призначена для системного опрацювання чернеток і швидких записів із каталогу `notes/Inbox`, їхньої валідації, систематизації за методологією **PARA** та інтеграції в локальний граф знань студента.

---

## 1. Загальні принципи та обмеження безпеки

> [!IMPORTANT]
> **Суворі правила обробки даних:**
> 1. **Ніколи не вигадувати джерела:** якщо поле `source` порожнє або джерело не згадано в тексті, залишайте `source: "не вказано"` або зберігайте оригінальний запис автора. Заборонено додумувати авторів, URL, посібники чи підручники.
> 2. **Збереження оригінального змісту:** не скорочуйте і не вилучайте авторські думки, тези, код чи математичні формули. Дозволяється лише структурування у стандартизовані H2-секції.
> 3. **Заборона самовільного переміщення/видалення:** **НІКОЛИ** не переміщуйте файл з `notes/Inbox` в іншу директорію і не видаляйте оригінал без явного підтвердження користувача в чаті. Спершу користувач повинен ознайомитися з пропозицією та надати згоду.
> 4. **100% Локальність:** не відправляти вміст нотаток у зовнішні сервіси чи хмарні API.

---

## 2. Алгоритм роботи з нотаткою

Коли користувач просить розібрати `notes/Inbox` або конкретну нотатку, виконайте такі кроки:

### Крок 1. Аналіз вхідного файлу
1. Прочитайте файл із `notes/Inbox/`.
2. Перевірте наявність та коректність YAML Frontmatter:
   - `title`: назва нотатки (має збігатися з назвою файлу без `.md`).
   - `created`: дата/час створення (зберегти оригінальну або встановити поточну).
   - `updated`: оновити до поточного часу.
   - `tags`: список нормалізованих тегів.
   - `status`: поточний статус (`draft`, `active`, `completed`, `archived`).
   - `type`: тип нотатки (`fleeting`, `project`, `area`, `resource`, `archive`, `lecture`).
   - `source`: джерело (суворо лише те, що вказано автором).

### Крок 2. Структурування за стандартом
Переконайтеся, що вміст нотатки організовано за трьома обов'язковими H2-секціями:
```markdown
## Короткий зміст
[1-3 лаконічні речення, які формулюють суть нотатки]

## Основні твердження
- [Ключова теза / спостереження / формула]
- [Наступне твердження]

## Пов'язані нотатки
- [[Назва існуючої нотатки]]
```

### Крок 3. Класифікація за методологією PARA
Визначте цільову категорію PARA на основі чітких критеріїв:

| Категорія | Критерії класифікації | Приклади |
| :--- | :--- | :--- |
| **`notes/Projects`** | Має конкретну мету, завдання та визначений дедлайн/кінцевий термін виконання. | Лабораторна робота, курсовий проєкт, підготовка до захисту звіту, конкретний реліз ПЗ. |
| **`notes/Areas`** | Довгострокова сфера відповідальності, навчальна дисципліна, підтримання стандарту знань без дедлайну. | Семестровий курс, вивчення мови програмування, підтримка конспектів лекцій, оглядові MOC. |
| **`notes/Resources`** | Довідкові матеріали, конспекти підручників, статті, шпаргалки, патерни проектування, які корисні в багатьох контекстах. | Довідник з Linux API, опис протоколу MESI, конспект книги Фаулера, гайд по синтаксису Dockerfile. |
| **`notes/Archives`** | Завершені або неактуальні проєкти, матеріали минулих семестрів, заархівовані звіти. | Захищена лабораторна робота №1, проєкти закритих курсів (`status: archived`). |

### Крок 4. Пошук та пропозиція зв'язків ([[Wikilinks]])
1. Проскануйте наявні нотатки в директоріях `notes/Projects`, `notes/Areas`, `notes/Resources`, `notes/Archives`.
2. Запропонуйте додати посилання на споріднені концепції за точними назвами файлів у форматі `[[Назва нотатки]]`.
3. Якщо нова нотатка розкриває фундаментальну тему — запропонуйте додати згадку про неї у відповідну оглядову MOC-нотатку (наприклад, `[[MOC - Комп'ютерні системи, Хмари та Штучний Інтелект]]`).

## 3. Обов'язковий формат відповіді користувачу

Кожна сесія обробки **обов'язково** завершується структурованим **Журналом запропонованих змін** та запитом на підтвердження дій:

### Шаблон звіту:

```markdown
### 📋 Журнал запропонованих змін для нотатки: "[Назва нотатки]"

| Параметр | Поточне значення | Пропозиція | Обґрунтування |
| :--- | :--- | :--- | :--- |
| **Категорія PARA** | `notes/Inbox` | `notes/[Projects/Areas/Resources/Archives]` | [Чому обрано саме цю категорію] |
| **Статус (`status`)** | `draft` | `active` / `completed` / `archived` | [Пояснення зміни статусу] |
| **Тип (`type`)** | `fleeting` | `project` / `area` / `resource` / `archive` | [Відповідний тип] |
| **Теги (`tags`)** | `[поточні]` | `[поточні, +нові-теги]` | [Чому додано нові теги] |
| **Джерело (`source`)** | `[оригінальне]` | `[збережено без змін]` | [Підтвердження автентичності] |

#### 🔗 Запропоновані зв'язки ([[Wikilinks]]):

- `[[Назва існуючої нотатки 2]]` — [короткий коментар щодо зв'язку]
